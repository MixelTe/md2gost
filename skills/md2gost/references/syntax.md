# Синтаксис md2gost

Сжатая справка по README md2gost. Ловушки и заголовки-ключевые слова описаны в `SKILL.md`, здесь
они не повторяются. В примерах картинок README ставит пробел между `]` и `(` из-за проблем
отображения; в настоящем документе пробела быть не должно.

## Текст

```md
*курсив*, **жирный**, ***жирный курсив***, `обратные кавычки`
[подпись ссылки](https://example.com)
Неразрывный пробел: 5&nbsp;кг
Разрыв строки без отступа:<br>следующая строка
```

Пустая строка разделяет абзацы. Перевод строки внутри абзаца сохраняется и добавляет отступ
(табуляцию) перед продолжением; `<br>` даёт разрыв без отступа. `<br><br>` — пустая строка.

`` `текст` `` по умолчанию выводится курсивом. Правило `!!rule backtick_mono <italic|off|on|outline>`:
`off` — обычный текст, `on` — моноширинный, `outline` — моноширинный в рамке.

## Заголовки

```md
# 1 Раздел
## 1.1 Подраздел
### 1.1.1 Пункт
```

Номер разделов пишется вручную (номер, пробел, название) или через `[#]`: `# [#] Раздел`,
`## [#] Подраздел`. Цифра, поставленная вручную в заголовке первого уровня, распознаётся, и
следующие `[#]` продолжают с неё. Ненумерованный заголовок — просто текст без номера.

## Списки

```md
* маркированный
- тоже маркированный

1. нумерованный
1. номер можно не менять
2) со скобкой

1. первый
	* вложенный (отступ табом)
2. второй
```

Знаки препинания в конце пунктов расставляются автоматически. Стиль маркеров:
`!!rule list unordered style <dash|bullet|keep>`, `!!rule list ordered style <bracket|dot|keep>`
(см. `rules.md`).

## Картинки

```md
![Подпись](imgs/schema.png)
![Подпись](imgs/schema.png){340}         ширина
![Подпись](imgs/schema.png){x265}        высота
![Подпись](imgs/schema.png){340x265}     ширина и высота
![Длинная подпись, <br>вторая строка](imgs/schema.png){340}
```

Картинка — на отдельной строке, путь относительно `.g.md`. Alt-текст становится подписью
«Рисунок N – Подпись». Markdown внутри подписи не работает, перенос — `<br>`. Если файла нет,
сборка падает с `File not exist`.

## Листинги

````md
```python Загрузка данных из CSV
import csv
```

```txt Конфигурация сервера
Текст без подсветки: язык может быть любым словом
```
````

Текст после языка — подпись «Листинг N – …». При разрыве листинга на страницы (PDF через Word)
подпись «Продолжение листинга N» добавляется сама. Строка листинга при шрифте 12 пт вмещает около
60–65 символов, длиннее — переносится; в коде для отчёта держи строки короче.

Подсветка синтаксиса: `!!rule code highlight` (по ГОСТ листинги чёрно-белые, так что для курсовой
обычно не нужна). Языки: html, xml, css, js, ts, jsx, tsx, json, bash, powershell, python, java,
c, cpp, csharp, go, rust, php, ruby, swift, kotlin, sql, yaml, markdown, docker, nginx.

## Таблицы

```md
Результаты измерений

| Параметр | До | После |
|:---------|:--:|------:|
| Время, с | 12 | 3     |
| Память<br>(пик), МБ | 512 | 128 |
```

Абзац непосредственно перед таблицей — подпись «Таблица N – …» (пустая строка между ними
допустима). Выравнивание — двоеточиями, вертикальные черты по краям необязательны, перенос в
ячейке — `<br>`, символ `|` внутри ячейки — `&#124;`. Широкую таблицу можно вынести в альбомный
раздел (`!!section landscape` … `!!section portrait`).

## Формулы

```md
Строчная: $v = \frac{s}{t}$, знак доллара в тексте: \$.

$$
E = mc^2
$$
```

LaTeX-синтаксис. `$$` блочной формулы — на отдельных строках. Кириллица (даже в `\text{}`)
работает только в блочной формуле: строчная с ней не конвертируется. С `!!rule numbering lazy` блочная
формула нумеруется сама; без него номер задаёт `[#]` или любой текст в скобках на строке прямо
перед формулой:

```md
(А.1)
$$
E = mc^2
$$

[energy]
$$
E = mc^2
$$
Как показано в формуле [energy], …
```

## Комментарии

```md
<!-- одна строка -->
<!-- несколько
строк -->
```

Поддерживаются только отдельно стоящие комментарии; текст после `-->` на той же строке тоже
удаляется. Директивы внутри комментария (`!!(…){}`, `!!rule`) не выполняются.

## Admonition

Выделенные блоки, синтаксис как в Docusaurus. Это не элемент ГОСТ — для курсовой не используй.

````md
:::note
Примечание. Внутри работает Markdown.
:::

:::warning[Свой заголовок]
Текст.
:::

:::tip[]
Без заголовка.
:::
````

Типы: `note`, `info`, `tip`, `warning`, `danger`. Оформление — правилами
`!!rule admonition <тип|all> …` (см. `rules.md`).

## Разрывы страниц и разделов

```md
---
```

`---` на отдельной строке — разрыв страницы.

```text
!!section [landscape|portrait] [from N|unpaged]
```

Разрыв раздела с параметрами следующих страниц. Параметры в любом порядке, неуказанные
наследуются:

- `!!section from 3` — нумерация страниц с 3 (после титульника и задания);
- `!!section landscape` / `!!section portrait` — ориентация;
- `!!section unpaged` — без номеров страниц;
- `!!section landscape from 3` — вместе.

## Колонтитулы

```md
!!header align=center
Инвентарный номер:<br>567.0004653-03 98 01-07
!!endheader

!!footer
| № изменения: ____ | Подпись: ____ | Стр. [!page] из [!pages] |
|:--|:--|--:|
!!endfooter
```

- `align=left|center|right`, по умолчанию `left`.
- Внутри — текст, inline-форматирование и одна таблица (на всю ширину, с границами).
- `[!page]` — номер текущей страницы, `[!pages]` — всего страниц.
- Действует с текущего раздела до следующего одноимённого оператора. `!!header none`,
  `!!footer none` отключают; `!!footer auto` возвращает стандартный номер страницы.
- Другой колонтитул на первой странице — сначала отдельный раздел через `!!section`.

## Автонумерация и ссылки

Нумеруются рисунки, таблицы, листинги, формулы, разделы и источники. Выражения в квадратных
скобках:

| Выражение | Где | Значение |
|---|---|---|
| `[#]` | в подписи | номер этого элемента с префиксом: «Рисунок 1 – » |
| `[#]` | в тексте | номер следующего нумеруемого элемента |
| `[#-1]`, `[#+2]` | в тексте | смещение от следующего элемента среди элементов его типа |
| `[имя]` | в подписи или заголовке | задаёт элементу имя (буквы, цифры, `_`, без пробелов, регистр важен) |
| `[имя]`, `[имя+1]` | в тексте | номер именованного элемента и смещение от него |
| `[[id]]` | в тексте | номер источника «[N]» |
| `[!pages]` `[!imgs]` `[!tables]` `[!codes]` `[!formulas]` `[!sources]` | где угодно | количество страниц, рисунков, таблиц, листингов, формул, источников |

```md
!!rule numbering lazy

Ниже на рисунках [#]–[#+1] показаны схемы, а в таблице [res] — результаты.

![Логическая схема](logic.png)
![[phys] Физическая схема](phys.png)

[res] Результаты нагрузочного теста

| Запросов/с | Задержка, мс |
|---|---|
| 100 | 12 |

Физическая схема (рисунок [phys]) …
```

Именованный элемент: в подписи рисунка `![[имя] Подпись](…)`, листинга
```` ```js [имя] Подпись ````, таблицы `[имя] Подпись` в абзаце-подписи, раздела `## [имя] Название`,
формулы `[имя]` на строке перед `$$`, приложения `## [имя] Название` внутри `# ПРИЛОЖЕНИЯ`
(ссылка даст букву «А», листинг внутри приложения — «А.1»).

Правила автонумерации:

- `!!rule numbering lazy` — `[#]` в подписях подставляется сам (именованные элементы работают
  как раньше);
- `!!rule numbering sections` — номера по разделам: «Рисунок 1.1», «Рисунок 2.1»;
- `!!rule numbering autoprefix off` — без слова «Рисунок»: `![[#] Кот]` → «1 Кот»,
  `![Рис. [#]: Кот]` → «Рис. 1: Кот».

`[!pages]` в DOCX без постобработки Word пустой, пока поле не обновлено.

## Вставка файлов

```text
!!(путь/к/файлу){"ключ": "значение"}
```

Тип определяется расширением, путь — относительно файла с директивой:

- **DOCX** — вставляется целиком; поля `{{ключ}}` внутри документа заполняются из параметров.
  Вложенные объекты доступны через точку: `{"student": {"name": "…"}}` → `{{student.name}}`,
  массивы — `{{students.0.name}}`.
- **PDF** — как есть, параметры пустые: `!!(title.pdf){}`.
- **Markdown** (`.md`, `.g.md`) — раскрывается в документ до рендера, со всем синтаксисом
  md2gost и шаблонизацией (см. `templating.md`).

DOCX и PDF вставляются только при экспорте в PDF через Word; вокруг вставки сами ставятся разрывы
страниц. Отсутствующий файл останавливает сборку даже в режиме DOCX. Соседние директивы разделяй
пустой строкой, иначе они склеятся в одну (`Cant parse doc dict`).

```md
!!(title.docx){
    "topic": "Сбалансированные деревья поиска",
    "group": "КЛМН-00-00",
    "name": "Иванов П. С."
}
!!section from 2
```

## Автозамены

При экспорте (исходник не меняется):

- `—` → `–`, ` - ` → ` – `; `"текст"` → `«текст»`; `<br>` → разрыв строки;
- `&nbsp;` неразрывный пробел, `&shy;` мягкий перенос, `&Tab;` табуляция, `&#x200B;` — ничего
  (чтобы обмануть парсер, например `[&#x200B;1]` для буквальных скобок);
- `&laquo; &raquo;`, `&Star;` → `*`, `&#124;` → `|`, `&amp;` → `&`, `&lt; &gt;`;
- греческие `&alpha;` … `&omega;`, `&Delta; &Sigma; &Omega;`; математические `&infin; &sum; &prod;
  &radic; &int; &part; &asymp; &ne; &le; &ge; &plusmn; &times; &divide;`; прочие `&copy; &reg;
  &trade; &sect; &para; &hellip; &bull; &middot; &deg; &euro; &permil;`;
- `[!page]`, `[!pages]`, `[!imgs]`, `[!tables]`, `[!codes]`, `[!sources]` — см. выше.

Неразрывные пробелы ставятся сами: после коротких служебных слов, между обозначением и номером
(«рисунок 1», «№ 5», «ГОСТ 123»), в инициалах, адресах, датах («2026 г.»), между числом и
единицей («15 кг», «25 %»). Дефисы внутри слов («веб-сервис», «UTF-8») становятся неразрывными.

## Метаданные

```md
!!rule title Отчёт по практической работе №3
!!rule author Иванов П. С.
!!rule ctime 2026-02-18
!!rule mtime 2026-02-18T12:30:00
!!rule etime 95
```

`title` и `author` видны в свойствах файла и заголовке окна PDF. `ctime` — дата создания (по
умолчанию дата создания `.g.md`), `mtime` — изменения (по умолчанию время рендера), `etime` —
время редактирования в минутах (по умолчанию случайное 30–120).
