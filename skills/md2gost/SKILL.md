# md2gost

md2gost превращает Markdown в DOCX и PDF, оформленные по ГОСТ 7.32: шрифты, отступы, подписи
«Рисунок 1 – …», автонумерация, оглавление, список источников, приложения. Исходник — файл
`.g.md`. CLI примет и обычный `.md`, но расширение VS Code включает подсветку, подсказки и кнопки
экспорта только для `.g.md`, поэтому новые файлы называй так.

Движок один, интерфейсов два: расширение VS Code (пользователь жмёт кнопку экспорта) и npm-пакет
`md2gost` с CLI и JS API. Синтаксис почти обычный Markdown, но несколько привычных конструкций
работают иначе и **тихо портят документ** — прочитай раздел «Чем md2gost отличается от Markdown»
до того, как писать текст.

## Порядок работы

1. **Осмотрись.** Если в проекте уже есть `.g.md`, повтори их шапку `!!rule`, стиль заголовков,
   именование картинок: единообразие с прошлыми работами пользователя важнее шаблонов скилла.
   Посмотри, где лежат картинки и есть ли титульный лист (DOCX/PDF), и нет ли методички с
   требованиями к оформлению.
2. **Напиши документ.** Новую работу начинай с шаблона: `assets/coursework.g.md` (курсовая, ВКР,
   отчёт о НИР) или `assets/report.g.md` (практическая, лабораторная). Справочники, читай по
   необходимости:
   - `references/syntax.md` — весь синтаксис: текст, картинки, таблицы, листинги, формулы,
     автонумерация и ссылки, разделы, колонтитулы, Admonition, вставки, автозамены;
   - `references/rules.md` — все правила оформления `!!rule` (шрифты, интервалы, заголовки,
     таблицы, листинги, списки) — нужен, когда требования вуза отличаются от умолчаний;
   - `references/templating.md` — Markdown-вставки с переменными, `{{#if}}`/`{{#for}}`, JS API.
3. **Собери DOCX**, если в окружении есть Node.js (раздел «Сборка»).
4. **Проверь результат** (раздел «Проверка»): предупреждения CLI и текст получившегося DOCX.
5. **Сообщи пользователю** коротко: где лежат файлы, что осталось сделать руками (обновить поля
   в Word, вставить титульник, заменить заглушки картинок) и какие решения ты принял сам — их
   стоит назвать, чтобы пользователь мог поправить.

## Чем md2gost отличается от Markdown

Каждый пункт проверен рендером. Это места, где привычки обычного Markdown дают испорченный
документ, часто без единого предупреждения.

- **Абзац пишется одной строкой.** Перевод строки внутри абзаца сохраняется в документе (как
  разрыв строки с отступом), а не склеивается, как в CommonMark. Не переноси прозу по ширине.
  Абзацы разделяй пустой строкой; разрыв строки без отступа — `<br>`.
- **`---` на отдельной строке — разрыв страницы**, а не горизонтальная линия. Не ставь его между
  разделами для красоты.
- **Квадратные скобки — это ссылки.** `[слово]` из букв, цифр и `_` md2gost считает ссылкой на
  нумерованный элемент: скобки исчезают, а если элемента с таким именем нет — остаётся слово и
  предупреждение «Неизвестная ссылка». `arr[i]` в тексте станет `arri`, «[1]» — «1». Код бери в
  обратные кавычки (`` `arr[i]` ``), буквальные скобки пиши как `[&#x200B;1]`. Обратный слеш
  `\[1\]` не помогает: слеши остаются в тексте.
- **`$` открывает формулу.** «стоит 5$ или 10$» превратится в формулу без предупреждения. Пиши
  `\$` или словами.
- **Кириллица ломает строчную формулу.** `$T_{ср}$` и даже `$T_{\text{ср}}$` не конвертируются
  (предупреждение `Formula was not converted`). В блочной формуле `$$ … $$` кириллица в `\text{}`
  работает — выноси такие формулы в блок.
- **Подписи не нумеруются вручную.** С `!!rule numbering lazy` подпись `![Кот](cat.png)` станет
  «Рисунок 1 – Кот», а `![Рисунок 1 - Кот](cat.png)` — «Рисунок 1 – Рисунок 1 – Кот». Без `lazy`
  номер ставится через `[#]` в подписи: `![[#] Кот](cat.png)`. Точку в конце подписи md2gost
  уберёт сам. В тексте тоже не пиши номера руками («на рисунке 3»): после правок они разъедутся,
  а `[#]` и именованные ссылки — нет.
- **Подписи берутся из соседних строк:** у рисунка — alt-текст `![подпись](путь)`, у таблицы —
  абзац непосредственно перед ней, у листинга — текст после языка в первой строке блока
  (```` ```python Обработка данных ````). Блок кода без такого текста выйдет без подписи и номера.
- **`[#]` в тексте указывает на следующий нумеруемый элемент** — рисунок, таблицу, листинг или
  формулу, что встретится первым. Два `[#]` подряд перед двумя рисунками дадут **один и тот же**
  номер. Ставь `[#]` прямо перед своим элементом; для «рисунки 2–4» пиши `[#]–[#+2]`. Смещение
  `[#+1]` считается среди элементов **того же типа**, что и следующий: «листинг [#], рисунок [#+1]»
  перед листингом и рисунком даст «рисунок 2». Для ссылок на элемент другого типа или издалека
  используй именованные элементы: `![[schema] Схема БД](db.png)` и «на рисунке [schema]».
- **Источники:** в тексте `[[id]]` → «[1]», в разделе `# СПИСОК ИСПОЛЬЗОВАННЫХ ИСТОЧНИКОВ` строки
  `[id] Описание`. Нумерация идёт по порядку первого упоминания, список сортируется сам.
- **Не поддерживаются** и выводятся как обычный текст: цитаты `>`, сноски `[^1]`, чекбоксы
  `- [ ]`, HTML-теги кроме `<br>` (в том числе `<sub>`/`<sup>`; индексы и степени пиши формулой
  `$H_2O$`, `$x^2$`). Вложенные списки делаются отступом табом.
- **Списки сами получают знаки препинания:** «,» или «;» после пунктов, «.» после последнего,
  «:» перед вложенным списком. Пиши пункты без завершающих знаков, со строчной буквы, как
  требует ГОСТ. Отключить: `!!rule list autopunctuation off`.
- **Автозамены:** `—` и ` - ` становятся `–`, `"текст"` — «текст», неразрывные пробелы ставятся
  сами (после предлогов, в «рисунок 1», «15 кг», «А. С. Пушкин»). Не расставляй `&nbsp;` вручную и
  не «исправляй» тире.
- **Комментарии** `<!-- … -->` пиши на отдельных строках: текст после комментария на той же
  строке тоже пропадёт. Удобно для служебных пометок и отключённых директив.
- **`!!rule` действует на весь документ**, где бы ни стоял; при повторе побеждает последний.
  Держи правила в шапке.
- **`{{…}}` в главном документе выводится как есть**, пока переменные не переданы через API.
  Шаблонизация работает во вставках `!!(часть.md){…}` — см. `references/templating.md`.

### Заголовки-ключевые слова

Заголовок **первого уровня** с одним из этих текстов (регистр не важен) включает автоматику ГОСТ:

| Заголовок | Что делает md2gost |
|---|---|
| `# РЕФЕРАТ` | Строка «Отчет N с., N рис., N табл., N лист., N источн.», первый абзац (ключевые слова) в верхний регистр, разрыв страницы после раздела |
| `# ОГЛАВЛЕНИЕ` | Оглавление Word по заголовкам (поле, заполняется в Word) |
| `# ТЕРМИНЫ И ОПРЕДЕЛЕНИЯ` | Список `* Термин: определение` превращается в таблицу с вводной фразой |
| `# ПЕРЕЧЕНЬ СОКРАЩЕНИЙ И ОБОЗНАЧЕНИЙ` | Вводная фраза, список `* HTML – …` без маркеров, разрыв страницы |
| `# ВВЕДЕНИЕ` | По центру; следующий заголовок начнётся с новой страницы |
| `# ЗАКЛЮЧЕНИЕ` | По центру, с новой страницы |
| `# СПИСОК ИСПОЛЬЗОВАННЫХ ИСТОЧНИКОВ` | С новой страницы; нумерует и сортирует источники `[id] …` по первому упоминанию `[[id]]` |
| `# ПРИЛОЖЕНИЯ` | Каждый `## [id] Название` — отдельное приложение с новой страницы, буквы А, Б, В; ссылка `[id]` в тексте → «А» |

Других ключевых слов нет. `# СОДЕРЖАНИЕ` оглавление не создаст, `# ИСТОЧНИКИ` и `# СПИСОК
ЛИТЕРАТУРЫ` не пронумеруют источники — это обычные заголовки. Если требования называют раздел
иначе, используй ключевое слово и скажи пользователю, что заголовок можно переименовать в Word.

Эти заголовки сами ставят разрывы страниц, поэтому не добавляй рядом с ними `---`: два разрыва
подряд дают пустую страницу. Чаще всего это `---` после текста введения перед `# 1 …`. Для
короткого отчёта по практике, где введение в пару строк, разрывы могут быть лишними: тогда пиши
`## Введение` (второй уровень автоматику не включает).

Разделы основной части нумеруются вручную: `# 1 Анализ предметной области`, `## 1.1 Обзор`
(номер, пробел, название, без точки после номера). Можно и автоматически: `# [#] Название`.

## Шапка нового документа

Типичная настройка под ГОСТ (её же предлагает README md2gost):

```
!!rule numbering lazy
!!rule headings alt_style_1
!!rule code title style italic
!!rule table title style italic
!!rule table heading style bold
!!rule hyphenation
!!rule title Название работы
!!rule author Фамилия И. О.
```

`numbering lazy` избавляет от `[#]` в подписях — для нового документа это лучший выбор.
Умолчания (Times New Roman 14 пт, интервал 1,5, абзацный отступ 1,25 см) уже соответствуют
ГОСТ 7.32. Если у пользователя есть методичка со своими требованиями, переведи их в правила из
`references/rules.md` и не меняй то, чего методичка не касается.

**Титульный лист** обычно готовит пользователь в Word. Он вставляется директивой
`!!(title.docx){"group": "…"}` (поля `{{group}}` внутри DOCX заполнятся), а следом
`!!section from 2` (или `from 3`, если есть ещё лист задания) начинает нумерацию страниц после
него. Вставка DOCX/PDF срабатывает **только при экспорте в PDF** (Windows + Word); в DOCX без
Word на её месте окажется строка `!!(путь){}`, а отсутствующий файл остановит сборку. Если
титульника нет, оставь директиву закомментированной и скажи пользователю. Несколько вставок
подряд (титульник, затем задание) разделяй пустой строкой: без неё md2gost склеит их в одну
директиву (`Cant parse doc dict`) и вторая пропадёт.

## Сборка

Нужен Node.js. Запуск без установки — `npx -y md2gost …`. Запускай из папки работы: по умолчанию
картинки и вставки должны лежать внутри текущей папки.

| Окружение | Команда | Результат |
|---|---|---|
| Linux, macOS, Windows без Word | `npx -y md2gost doc.g.md -d` | DOCX без постобработки Word |
| Windows + Microsoft Word | `npx -y md2gost doc.g.md -f pdf -k` | PDF и DOCX с обновлёнными полями |

Без `-d` на Linux и macOS команда завершится ошибкой `NOWIN` с кодом 1, хотя DOCX запишет, — с
`-d` выход чистый. Прочие опции: `-o путь.docx` или `-o папка/`, `-f docx|pdf`,
`-k` (оставить промежуточный DOCX при PDF), `--check-files-inside <папка>`, `-x` (разрешить файлы
вне папки).

Чего нет в DOCX, собранном с `-d` (это делает постобработка в Word), — скажи пользователю:

- **оглавление и `[!pages]` пустые**: это поля Word. Пользователь открывает DOCX в Word,
  Ctrl+A → F9 (или ПКМ → «Обновить поле»). Экспорт PDF в расширении VS Code на Windows делает
  это сам;
- нет надписей «Продолжение таблицы N» на разрывах таблиц и листингов;
- не вставлены DOCX/PDF-файлы `!!(…){}` (Markdown-вставки работают).

Если пользователь экспортирует сам в VS Code и Node.js ставить не хочет — не собирай, но
предупреди, что проверку ниже ты не делал.

Грубый предпросмотр PDF без Word: `soffice --headless --convert-to pdf doc.docx`, если установлен
LibreOffice. Вёрстка отличается от Word, оглавление останется пустым — это для твоей проверки,
не итог для пользователя.

### Ошибки и предупреждения

- `Line N: File not exist: путь` — нет картинки или вставляемого файла; путь считается от
  `.g.md` (у вставки — от неё самой). Сборка прерывается на первой такой ошибке. Если скриншотов
  ещё нет, для проверочной сборки создай временные заглушки и скажи пользователю, какие файлы
  заменить.
- `Line N: Неизвестная ссылка [x]` — опечатка в имени ссылки или квадратные скобки в тексте (см.
  выше). Документ собирается, но текст в этом месте испорчен — исправь каждое такое место.
- `В тексте отсутствуют ссылки на источник: id` — источник есть в списке, но в тексте нет
  `[[id]]`. По ГОСТ на каждый источник ссылаются: добавь ссылку или убери источник.
- `Wrong format of ТЕРМИНЫ И ОПРЕДЕЛЕНИЯ` — сразу после заголовка нужен список `* Термин: …`.
- `Wrong rule: …`, `Rule "…" wrong value` — опечатка в `!!rule` (см. `references/rules.md`).
- `Formula was not converted` — ошибка LaTeX или кириллица в строчной формуле.
- `Cant parse doc dict` — неверный JSON в параметрах `!!(…){…}` или две вставки без пустой
  строки между ними.
- `Macros must be enabled to render PDF output` — `-f pdf` вместе с `-d`; PDF без Word не получить.
- Ошибка `userInput` про путь вне папки — запусти CLI из корня работы или добавь `-x`.

## Проверка

1. Добейся сборки без предупреждений.
2. Выведи текст DOCX скриптом скилла (Node.js, без зависимостей):

   ```bash
   node <папка скилла>/scripts/docx-text.mjs doc.docx            # весь документ
   node <папка скилла>/scripts/docx-text.mjs doc.docx --grep "Рисунок|Таблица|Листинг"
   ```

   Он печатает абзацы со стилем, таблицы строками, разрывы страниц, поля Word и формулы.
   Проверь:
   - подписи «Рисунок N – …», «Таблица N – …», «Листинг N – …» идут по порядку, без двойных
     префиксов;
   - ссылки в тексте получили те номера, на которые ты рассчитывал;
   - в тексте не осталось `$`, `\`, `>`, `[^`, HTML-тегов и пропавших скобок;
   - абзацы не разорваны лишними `↵`, разрывы страниц стоят там, где задуманы, и нигде нет
     двух разрывов подряд (это пустая страница).
3. Сверь документ с требованиями методички, если она есть.

## Программный API

Для сборки из своего кода: `import renderMarkdown from "md2gost"`, затем
`await renderMarkdown({ input: "./report.g.md", output: "./report.docx", disableMacros: true })`.
Результат — `{ filePath, warnings }`, ошибка — `MDRenderError` с полями `code`, `warnings`.
Переменные для главного документа, шаблоны и лимиты — в `references/templating.md`.

Полная документация — README репозитория: https://github.com/MixelTe/md2gost
