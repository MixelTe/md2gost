# Разметка отчёта

Этого справочника достаточно для обычного отчёта: текст, разделы, рисунки, таблицы, листинги, формулы, ссылки, источники и вставка титульника. Примеры показывают синтаксис; названия, код и утверждения адаптируй к своей работе. Редкие возможности перечислены в конце со ссылками на README.

## Текст, списки и комментарии

Используй `.g.md` в UTF-8. Каждый обычный абзац записывай одной физической строкой, абзацы разделяй пустой строкой: внутренние переводы строк сохраняются в документе. Не подгоняй страницы пустыми абзацами. Отдельная строка `---` означает разрыв страницы.

```md
Обычный абзац с *курсивом*, **полужирным текстом** и `именем_метода`.

Второй абзац. Ссылка на сайт: [документация](https://example.com).

<!-- Рабочий комментарий не попадёт в печатный текст. -->

---

Абзац на новой странице.
```

Обратные кавычки выделяют код внутри предложения; по умолчанию он отображается курсивом. Если нужен именно моноширинный шрифт, добавь `!!rule backtick_mono on`. Обычный URL без конструкции `[текст](адрес)` автоматически не становится гиперссылкой. Литеральные квадратные скобки, доллар и другие служебные символы экранируй: `\[имя]`, `\$`, `\*`. Внутри кода и формул такое Markdown-экранирование не требуется. Неразрывный пробел можно записать как `&nbsp;`.

```md
Были выполнены следующие действия:

1. создана база данных
1. добавлены записи

Система поддерживает:

* добавление записей
* поиск записей

Этапы проверки:

1. подготовка данных
	* добавление товара
	* добавление заказа
2. выполнение запроса
```

Вложенность списка задавай табуляцией. У элементов списков утилита автоматически расставляет запятые или точки с запятой и завершающую точку. Для отключения этой обработки есть `!!rule list autopunctuation off`.

## Заголовки и нумерация

Для новых отчётов удобно включить ленивую нумерацию:

```md
!!rule numbering lazy
```

Она добавляет номера в подписи рисунков, таблиц и листингов, а также номера блочных формул. Подписи пиши без вручную вписанных «Рисунок 1» или «Листинг 2». Номера обычных разделов и подразделов вписывай явно в текст заголовков.

Если раздел с известным служебным названием уже содержит готовый текст и его не нужно преобразовывать автоматически, экранируй название: `# \РЕФЕРАТ`, `# \ТЕРМИНЫ И ОПРЕДЕЛЕНИЯ`. Обратный слеш не попадёт в результат, заголовок останется обычным разделом и сохранится в оглавлении. Для автоматического оглавления используй неэкранированный `# СОДЕРЖАНИЕ` или `# ОГЛАВЛЕНИЕ`.

По умолчанию используй три ненумерованные части первого уровня, а этапы внутри «Хода работы» нумеруй со второго уровня:

```md
# ВВЕДЕНИЕ

Цель работы — реализовать обработку заказов.

# ХОД РАБОТЫ

## 1 Создание базы данных

Была создана база данных.

### 1.1 Связи таблиц

Заказы были связаны с клиентами и товарами.

## 2 Получение списка товаров

Был выполнен запрос к таблице товаров.

# ЗАКЛЮЧЕНИЕ

Была реализована выборка товаров по заданным условиям.
```

Вместо «Введения» допустима «Цель работы», вместо «Заключения» — «Вывод». Число знаков `#` задаёт уровень заголовка от 1 до 6. При другой заданной структуре уровни и номера могут отличаться, например `# 1 Реализация`, `## 1.1 Получение данных`, `# 2 Результаты`. В начало обычных заголовков не ставь маркеры автонумерации или идентификаторы. На разделы ссылайся явно: «в подразделе 1.1». При перестановке разделов обновляй их номера и ссылки на них.

Если оглавление полезно по числу разделов или разветвлённости подразделов, по умолчанию добавь перед введением `# СОДЕРЖАНИЕ` (или `# ОГЛАВЛЕНИЕ`). После заголовка ничего не перечисляй: оглавление создаётся автоматически. Титульник, если предусмотрен, размещай перед ним; синтаксис вставки приведён ниже. Для короткой работы с несколькими простыми пунктами оглавление обычно не требуется. Прямые требования задания и пользователя к структуре имеют приоритет.

Если требуется нумерация рисунков, таблиц, листингов и формул по разделам, добавь `!!rule numbering sections`: номера объектов будут вида `1.1`, `1.2`, `2.1`. Основной раздел задаёт целый номер в начале заголовка любого уровня: `# 1 …` или `## 1 …`. Подразделы `1.1` и `1.1.` не сбрасывают счётчики. Поэтому правило работает и для этапов второго уровня внутри ненумерованного «Хода работы». Без явных номеров основных разделов учитываются заголовки первого уровня. Без этого правила нумерация каждого вида объектов сквозная.

## Ссылки на элементы

| Выражение в тексте | Цель |
|---|---|
| `[i#]` | Следующий рисунок |
| `[t#]` | Следующая таблица |
| `[c#]` | Следующий листинг |
| `[f#]` | Следующая формула |
| `[i#-1]` | Предыдущий рисунок |
| `[i#+1]` | Номер следующего рисунка плюс один |
| `[result]` | Элемент с идентификатором `result` |

У всех четырёх типов доступны смещения `+N` и `-N`; другие виды элементов пропускаются. Смещение вычисляет номер относительно ближайшего следующего или предыдущего элемента нужного вида, а не ищет произвольный элемент по всему документу. Для повторных ссылок, ссылок через границу раздела и удалённых элементов предпочитай именованные идентификаторы.

В тексте используй типизированные ссылки на ближайшие элементы и именованные ссылки для повторных обращений. Чтобы не перепутать соседние листинг и рисунок, указывай тип каждой ссылки:

````md
!!rule numbering lazy

Был выполнен запрос для получения списка товаров (листинг [c#], рисунок [i#]).

```sql Выборка товаров по цене
SELECT name, price
FROM products
ORDER BY price;
```

<!-- Выполнить запрос на данных задания, сделать скриншот результата и заполнить путь ниже. -->
![Результат выборки товаров]()
````

Для именованной ссылки поставь идентификатор в начало подписи. Если на рисунок, таблицу, листинг или формулу ссылаются только типизированными выражениями, идентификатор не добавляй. В подписях рисунков, таблиц и листингов обычный `[id]` задаёт собственный номер элемента; типизированные `[i#]` и подобные остаются ссылками на другие элементы.

Если подпись состоит только из идентификатора, выводятся вид и номер без тире: «Рисунок 1», «Таблица 1» или «Листинг 1».

Идентификаторы состоят из латинских или кириллических букв, цифр и `_`, без пробелов; регистр учитывается. Для ссылок выбирай понятные имена и не используй одно имя для разных элементов.

```md
!!rule numbering lazy

Результат представлен на рисунке [selection_result].

![[selection_result] Результат выборки товаров]()

На рисунке [selection_result] записи расположены по возрастанию цены.
```

## Изображения и размеры

Объявление рисунка занимает одну строку: `![Подпись](путь){размер}`. Между `]` и `(` пробела нет. Размер записывается **после закрывающей круглой скобки пути**, вне подписи и пути; он необязателен. Числа задаются в пикселях, без `px`, `см` и других суффиксов. Используй латинскую `x`, а не кириллическую `х` или знак `×`.

```md
!!rule numbering lazy

![Исходный размер](imgs/result.png)

![Ширина 400 пикселей](imgs/result.png){400}

![Высота 250 пикселей](imgs/result.png){x250}

![Ширина 400 и высота 250 пикселей](imgs/result.png){400x250}

![Длинная подпись<br>с переносом строки](imgs/result.png){400}

![Файл с пробелами в пути](<imgs/query result.png>){400}
```

При задании только ширины или высоты пропорции сохраняются. Два числа задают обе стороны и могут исказить пропорции. Слишком большой рисунок автоматически уменьшается до допустимого размера. Поддерживаются PNG, JPG, GIF, BMP и SVG. Путь к локальному изображению вычисляется относительно содержащего его `.g.md`; внутри Markdown-вставки — относительно вставляемого файла. Адрес сайта не заменяет локальный файл изображения: сначала сохрани нужный материал доступными средствами.

Если изображения нет, оставь именно пустой путь. Размер при этом можно сохранить:

```md
!!rule numbering lazy

Результат выполнения представлен на рисунке [i#].

<!-- Выполнить запрос и сделать скриншот результата. Сохранить кадр в imgs/result.png и заполнить путь рисунка ниже. -->
![Результат выполнения запроса](){400}
```

Рендер выдаст предупреждение, сохранив место рисунка, подпись, нумерацию и ссылки. Не придумывай имя отсутствующего файла в самом пути. Планируемое имя и способ получения кадра укажи в HTML-комментарии. Если текстовый результат ещё предстоит получить, оставь пропуск или пустой раздел с комментарием о том, что выполнить и что вписать.

## Таблицы

Абзац непосредственно перед таблицей считается её названием. Поэтому вводный абзац со ссылкой и само название должны быть разными абзацами. При ленивой нумерации достаточно названия без номера; для именованной таблицы начни его с `[id]`.

```md
!!rule numbering lazy

Сравнение приведено в таблице [t#].

[storage] Сравнение способов хранения

| Способ | Назначение | Число записей |
|:---|:---:|---:|
| Файл | Хранение настроек | 1 |
| База данных | Хранение связанных<br>записей | 20 |

В таблице [storage] приведены два способа хранения.
```

Вторая строка задаёт столбцы: `:---` — слева, `:---:` — по центру, `---:` — справа. Первая строка — заголовки ячеек; по умолчанию они выравниваются по центру. Если им нужно выравнивание своих столбцов, добавь `!!rule table heading align keep`. В ячейке `<br>` переносит строку. Название таблицы по необходимости выравнивается правилом `!!rule table title align right` или `left`/`center`.

Обычно таблице требуется название. Если по согласованному оформлению нужна таблица без видимой подписи, запиши отдельный абзац `<br>` перед ней, чтобы вводный текст не стал названием:

```md
!!rule numbering lazy

Были получены следующие значения.

<br>

| Показатель | Значение |
|---|---:|
| Количество | 20 |
```

Пустая подпись не получает ленивый номер. Таблица при этом остаётся в общем счётчике таблиц. Обычный пробел или пустая строка вместо `<br>` не защищают вводный абзац от превращения в название.

## Листинги

После трёх обратных кавычек в открывающей строке укажи язык, пробел и название листинга. Закрывающая строка содержит только три обратные кавычки. Для текстового вывода используй `text`. При ленивой нумерации номер и слово «Листинг» в названии не нужны; именованный маркер записывается перед названием, после языка.

````md
!!rule numbering lazy

Обработчик приведён в листинге [handler].

```python [handler] Обработчик заказа
def total(price, quantity):
    return price * quantity
```

Результат вызова приведён в листинге [c#].

```text Результат вычисления
150
```
````

Ограды листинга пиши от начала строки. У извлечённого фрагмента убирай лишний общий отступ: например, метод без окружающего класса начинай с `def`, а не с четырёх пробелов. Внутренние отступы тела метода и вложенных конструкций сохраняй. Если для понимания нужна окружающая конструкция, включи её в листинг. Это изменение представления фрагмента в отчёте, а не исходного кода проекта.

Не заменяй листинг отступами или обычным абзацем. Для длинных таблиц и листингов офисная постобработка добавляет подписи продолжения; вручную дублировать их не нужно. Для подсветки кода есть `!!rule code highlight`, по умолчанию она выключена.

## Формулы

Строчную формулу записывай как `$v = \frac{s}{t}$`. Для отдельной формулы открывающий и закрывающий `$$` ставятся на отдельных строках. Внутри используется математический LaTeX, а не команды оформления документа вроде `\begin{document}`.

```md
!!rule numbering lazy

Скорость равна $v = \frac{s}{t}$. Связь энергии и массы приведена в формуле [f#].

[energy]
$$
E = mc^2
$$

В формуле [energy] масса обозначена через $m$.
```

Отдельная строка `[energy]` непосредственно перед открывающим `$$` назначает формуле идентификатор и автоматический номер. С ленивой нумерацией номер появится и без идентификатора.

Если по заданию нужен фиксированный номер, вместо идентификатора запиши его в круглых скобках непосредственно перед формулой:

```md
(А.1)
$$
E = mc^2
$$

В формуле А.1 приведена связь энергии и массы.
```

Идентификатор и фиксированный номер — разные варианты. Фиксированное значение в тексте указывай явно; не рассчитывай, что типизированная ссылка повторит вручную заданную строку номера.

## Специальные разделы и приложения

Не добавляй структуру курсовой в короткую лабораторную без необходимости. Для большой работы используй нужные разделы первого уровня: `# РЕФЕРАТ`, `# СОДЕРЖАНИЕ` (или `# ОГЛАВЛЕНИЕ`), `# ТЕРМИНЫ И ОПРЕДЕЛЕНИЯ`, `# ПЕРЕЧЕНЬ СОКРАЩЕНИЙ И ОБОЗНАЧЕНИЙ`, `# ВВЕДЕНИЕ`, `# ЗАКЛЮЧЕНИЕ`, `# СПИСОК ИСПОЛЬЗОВАННЫХ ИСТОЧНИКОВ` (или `# СПИСОК ЛИТЕРАТУРЫ`), `# ПРИЛОЖЕНИЯ`.

После заголовка содержания не пиши список разделов и страницы вручную: оглавление создаётся автоматически. После `# РЕФЕРАТ` первой строкой запиши ключевые слова, затем текст реферата. Утилита добавит строку со статистикой и переведёт ключевые слова в верхний регистр.

```md
# ТЕРМИНЫ И ОПРЕДЕЛЕНИЯ

* Запись: совокупность полей одной строки таблицы
* Ключ: поле для однозначной идентификации записи

# ПЕРЕЧЕНЬ СОКРАЩЕНИЙ И ОБОЗНАЧЕНИЙ

* БД – база данных
* СУБД – система управления базами данных
```

Термины записываются списком в формате `Термин: определение`; из него создаётся таблица без номера обычной таблицы. Сокращения также записываются списком. Вводные фразы этих разделов утилита добавляет сама.

```md
!!rule numbering lazy

Полный код приведён в приложении [full_code].

# ПРИЛОЖЕНИЯ

## [full_code] Полный код

<!-- Вставить полный код из проекта. -->
```

Приложения оформляются отдельным механизмом: каждое объявляй заголовком второго уровня с идентификатором. Оно начнётся с новой страницы и получит букву: `ПРИЛОЖЕНИЕ А`, `ПРИЛОЖЕНИЕ Б` и далее. Ссылка `[full_code]` выведет букву без слова «Приложение». Самостоятельно добавлять буквенный префикс в заголовок приложения не нужно; явная цифровая нумерация выше относится к обычным разделам и подразделам.

## Источники

Для ссылки на источник используй двойные квадратные скобки `[[SourceKey]]`, для группы — `[[SourceA], [SourceB]]`. Обычное `[SourceKey]` в основном тексте означает ссылку на элемент отчёта и не заменяет ссылку на литературу.

В разделе источников записывай `[SourceKey] Библиографическое описание` без двоеточия после идентификатора и без вручную проставленных номеров. Каждую запись отделяй пустой строкой. Утилита нумерует и сортирует источники по первому упоминанию в тексте.

```md
Для оформления ссылок использовалось описание синтаксиса md2gost [[md2gost]].

# СПИСОК ИСПОЛЬЗОВАННЫХ ИСТОЧНИКОВ

[md2gost] md2gost: документация проекта. URL: https://github.com/MixelTe/md2gost
```

Реквизиты бери из проверенных источников. Не создавай вымышленные авторов, статьи, URL и даты обращения. Для описания собственной реализации не требуется внешняя ссылка в каждом предложении. Предметные ссылки подтверждают содержание работы и не являются рассказом о подготовке отчёта по чужому образцу.

## Титульник, другие файлы и секции

Используй предоставленные файлы и реальные имена полей шаблона. Не придумывай ФИО, группу, руководителя, подписи и число титульных страниц. Директива вставки записывается отдельным блоком: `!!(путь){JSON-параметры}`. Путь вычисляется относительно файла с директивой; для вставки без параметров оставь `{}`.

```md
!!(title.docx){
    "topic": "Обработка данных",
    "name": "ФИО автора из предоставленных сведений"
}
!!section from 2

# ВВЕДЕНИЕ

Была реализована обработка данных.
```

Это пример синтаксиса, а не готовые реквизиты. В шаблоне DOCX значения подставляются в поля `{{topic}}`, `{{name}}`. Если перед основным текстом вставляется одна страница, `!!section from 2` начинает его нумерацию со второй. Число выбирай по реальному составу материалов; для двух предшествующих страниц подходит `!!section from 3`.

PDF-вставка имеет вид `!!(title.pdf){}`. Внешние DOCX/PDF подключаются только при экспорте PDF. Если PDF не запрошен, корректный блок вставки достаточен; фактическое объединение не считай блокером подготовки исходника или основного DOCX.

Markdown-вставка `!!(sections/introduction.g.md){}` раскрывает содержимое файла и для DOCX, и для PDF. Вложенные изображения и вставки считаются относительно этого файла. Для повторяемого фрагмента можно передать переменные:

```md
!!(sections/author.g.md){"name": "Иванов И.И."}
```

В файле `sections/author.g.md` значение используется как `Автор: {{name}}`. Не записывай незаполненные шаблонные выражения вместо обычных пропусков, если шаблонизация не нужна.

Для широкой таблицы можно переключить ориентацию и затем вернуть её:

```md
!!section landscape

<!-- Здесь разместить широкую таблицу с подписью. -->

!!section portrait
```

`!!section` создаёт разрыв раздела с новой страницы. Параметр `from N` задаёт начальный номер страницы, `unpaged` отключает отображение номеров в разделе. Без параметра нумерации сохраняется сквозной счёт. Не добавляй `---` непосредственно перед секцией ради того же разрыва страницы.

## Редкие возможности

Обычный отчёт не требует перечисленных ниже возможностей. При необходимости прочитай соответствующий раздел документации:

* [Колонтитулы](https://github.com/MixelTe/md2gost#колонтитулы): блоки `!!header` / `!!footer`, номера страниц и таблицы в колонтитулах.
* [Блоки Admonition](https://github.com/MixelTe/md2gost#блоки-admonition): выделенные примечания и предупреждения.
* [Автонумерация](https://github.com/MixelTe/md2gost#автонумерация): счётчики количества элементов и дополнительные настройки ссылок.
* [Markdown-вставки и шаблонизация](https://github.com/MixelTe/md2gost#markdown-вставки-и-шаблонизация): условия, циклы и сложные переменные.
* [Автозамены](https://github.com/MixelTe/md2gost#автозамены): неразрывные пробелы и управление типографикой.

Требования к шрифтам, интервалам и выравниванию проверяй по отдельному справочнику стилей. Если ссылка или справочник недоступны, не придумывай отсутствующие директивы; продолжай доступную часть работы и уточни действительно необходимое.
