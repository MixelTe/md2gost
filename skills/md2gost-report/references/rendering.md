# Рендер и версии

Читай этот файл только при явной просьбе создать DOCX или PDF. Для одного `.g.md` не проверяй версии, не ищи обновления и не обсуждай их с пользователем.

## Выбор поставки

Для заказанного рендера используй последнюю опубликованную версию md2gost. Скилл и утилита поставляются согласованно; справочники описывают текущее поведение, без исторических оговорок о возможностях.

Через используемый средой npm-реестр можно узнать актуальную версию командой `npm view md2gost@latest version`. Зафиксируй выбранный номер на время этого рендера, чтобы проверять метаданные и результат одной поставки. Для запуска подходит `npx --yes --package md2gost@<версия> -- md2gost ...`. Соблюдай разрешения среды на сеть и загрузку пакетов; зависимости проекта ради рендера не меняй.

Если получить последнюю поставку невозможно, используй доступную. Не выдавай её за последнюю. Недоступность проверки обновлений сама по себе не блокирует рендер.

## Две независимые версии

В YAML-заголовке основного `SKILL.md`:

* `metadata.version` — версия инструкций и справочников скилла;
* `metadata.md2gost-version` — версия утилиты, которой соответствует описание.

Версию скилла меняют при изменении его инструкций или справочников; новый выпуск утилиты сам по себе не требует нового номера скилла.

Версию выбранной утилиты получай через `md2gost --version`, метаданные поставляемого с ней скилла — через `md2gost --skill-info`. Обе команды работают без входного файла и не выполняют рендер. При запуске через npx указывай один и тот же выбранный номер пакета:

```sh
npx --yes --package md2gost@<версия> -- md2gost --version
npx --yes --package md2gost@<версия> -- md2gost --skill-info
```

В JSON `--skill-info` поле `version` содержит фактическую версию утилиты, `skill.version` — независимую версию скилла, `skill.md2gostVersion` — соответствующую ему версию утилиты, `skill.path` — абсолютный путь к основному `SKILL.md`. Сравни фактическую версию утилиты с `metadata.md2gost-version` используемого скилла. Сравнивай версии как semver, а не строки.

* **Утилита совпадает с указанной:** выполняй рендер без сообщения о версиях.
* **Утилита новее:** сравни `skill.version` из `--skill-info` с `metadata.version` используемого скилла. Если версия скилла та же, пользователя не беспокой. Если она новее, предложи обновить скилл; рендер продолжай, не ожидая обновления. `skill.path` позволяет найти файлы новой поставки. Без согласия установленный скилл не перезаписывай.
* **Утилита старее:** предупреди пользователя, что результат может зависеть от различия версий. Всё равно попробуй выполнить рендер. При проверке предупреждений и результата учитывай возможное несоответствие версии утилиты, не подменяя этим диагностику реальной ошибки.

Для сравнения достаточно YAML-заголовка нового скилла; используемые инструкции и справочники без согласия пользователя не заменяй. Если метаданные скилла из новой поставки недоступны, продолжай рендер и не объявляй скилл устаревшим без сравнения. Не повторяй одно предложение обновиться при каждом промежуточном рендере одной задачи.

## Запуск

Для DOCX:

```sh
npx --yes --package md2gost@<версия> -- md2gost "report.g.md" --format docx -o "report.docx"
```

Для PDF:

```sh
npx --yes --package md2gost@<версия> -- md2gost "report.g.md" --format pdf -o "report.pdf"
```

`<версия>` заменяется выбранным номером пакета, имена — путями текущей работы. Если нужен также промежуточный DOCX при PDF-экспорте, добавь `--keep-intermediate-docx`. Для выбранного явно офиса доступен `--engine word` или `--engine libreoffice`, без указания используется `auto`.

Внешние DOCX/PDF-вставки включаются при PDF-экспорте. Отсутствие запроса PDF не является причиной отклонять подготовку основного DOCX с корректными блоками вставок.

## Проверка результата

После экспорта проверь, что создан запрошенный файл, и прочитай предупреждения. Если доступна текстовая выгрузка, сверь существенное содержание с исходником. Оформление проверяй визуально только по просьбе проверить готовый документ или при исправлении проблемы, которую можно увидеть только после рендера. В этих случаях осмотри страницы, связанные с запросом, и сообщи о выполненной проверке.

Пустые пути и отсутствующие изображения дают предупреждения и сохраняют подписи. Перечисли такие места отдельно; не удаляй их из исходника для получения формально чистого журнала.

Если экспорт завершился ошибкой, сохрани исходник и доступный восстановленный DOCX. Сообщи фактическую ошибку и выполненные проверки. Предупреждение о версии не означает, что несуществующий или повреждённый выходной файл можно объявить готовым.
